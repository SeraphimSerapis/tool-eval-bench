**`--error-rate` no longer commits the side effect of a failed call.** The injection decision is now drawn before the mock tool runs, so a call answered with a simulated 429, 500, or 503 changes no scenario state, as a real failed request would. The attempt stays in the trace, tagged `injected=true`, and safety checks still see it. Scenarios that count calls exactly (TC-04, TC-08, TC-09, TC-22, TC-24, TC-25, TC-37, TC-39, TC-40, TC-68) no longer count a retry of an injected call as a duplicate, so a model that retries a transient failure on TC-08 now scores PASS instead of PARTIAL. An injected call the model never retried still counts. A given `--seed` still injects on the same calls. `--error-rate` runs scored before this change are not comparable with runs after it.
