`--probe` now exits 2 with `invalid_response` when the model listing answers 2xx with a body that is not a JSON object, such as a proxy's sign-in page, matching the pre-flight check. It used to exit 1 with a raw JSON parse error, which a readiness loop treats as "not up yet" and retries forever. The console prints "Invalid response", and the `--json` `probe_result` event carries `"error_code": "invalid_response"`. A JSON listing whose entries are not all model objects now reports ready with the model IDs it can read instead of failing.
