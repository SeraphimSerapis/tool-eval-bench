Every run one CLI invocation stores now shares a `session_id`, kept in a new indexed `scenario_runs.session_id` column (SQLite schema version 5). Perf, plugin, spec-bench, context-pressure, and scored runs, including every trial, carry the same id, and a resume joins the session of the run it resumes. A run whose execution context could not be collected joins the session too. The id is not part of the run ID or the config fingerprint and does not appear in reports or `export`. Under `--json`, the `run_saved` event carries it as `session_id`. Older rows keep a NULL session. `history` shows the first 8 characters of each run's session, and `card` accepts a unique prefix of at least 6, in either case.
