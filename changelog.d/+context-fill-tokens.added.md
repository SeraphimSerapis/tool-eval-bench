**`--context-fill-tokens N` fills a fixed number of tokens before each scenario.** `--context-pressure` takes a share of the window, so the same ratio puts models with different windows at different depths. The new flag injects exactly N tokens of filler, calibrated with the server's `/tokenize` where available, so a failure seen at a known depth (for example tool calls breaking above 135K tokens) can be reproduced on every model. The window is still detected only to refuse a fill that leaves no room for the scenario. Resume and the config fingerprint compare the requested count instead of the ratio. The flag cannot be combined with `--context-pressure` or `--context-pressure-sweep`.
