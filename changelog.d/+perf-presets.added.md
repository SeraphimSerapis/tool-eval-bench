**Throughput presets** with `--perf-preset {short,long}`. `short`, the default, is the existing sweep, and its runs keep their config fingerprint. `long` adds a long-context sweep in two llama-benchy passes stored as one run: concurrency 1, 2, and 4 at depth 0, then concurrency 1 at depths 16384 to 131072 with llama-benchy's `--enable-prefix-caching`, so each depth reports a cold prefill and a cached-prefix follow-up. Depths that do not fit the served context window are skipped, and a rough runtime estimate for the depth pass is printed after the first pass. `--pp`, `--tg`, `--depth`, `--concurrency`, and `--benchy-runs` still override the preset. The preset name is stored in the perf and scored run configs, outside the fingerprint, and reads `custom` when an override changed the grid. A scored run also stores a multi-pass plan as `perf_passes`. Throughput failures are counted in grid cells everywhere, and a pass that did not finish is recorded as `incomplete`, on the perf row or under a scored run's `scores.throughput`. Concurrent throughput rows now also store llama-benchy's measured per-request decode rate as `tg_req_tps`.
