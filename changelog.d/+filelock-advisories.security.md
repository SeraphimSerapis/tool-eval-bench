**Locked `filelock` moves to 4.2.4 for three advisories.** `uv.lock` pinned filelock 3.32.2, which is affected by [GHSA-v4x8-3wr5-3wq8](https://github.com/advisories/GHSA-v4x8-3wr5-3wq8) (high), [GHSA-9vhv-jxww-xfm5](https://github.com/advisories/GHSA-9vhv-jxww-xfm5), and [GHSA-567q-5qvw-pf92](https://github.com/advisories/GHSA-567q-5qvw-pf92). Another local user who can write to the lock's directory could make `ReadWriteLock` overwrite or unlink the lock user's files, or on Windows stall `SoftFileLock` past its timeout. filelock only arrives through the `hf` and `perf` extras and the `dev` toolchain. The project never takes these locks itself, but `huggingface-hub` falls back to `SoftFileLock` for its dataset cache on filesystems without `flock`, which reaches the Windows advisory. The fix applies to the Docker image and `uv sync` checkouts. A `pip install` resolves filelock on its own and is unaffected by the lock.
